# 新規プロジェクトの進め方（段0〜4）

新規プロジェクトの立ち上げ時と、段を切り替えるときに読む。数値はすべて**目安**で、実際のプロジェクトで試して直す前提（変えたら決定ログへ1行）。

役割：人は「選ぶ・見る」、AIは「調べる・案を出す・反対する」。調査・相談の決まりは`docs/ai-consulting-rules.md`。成果物は各プロジェクトの`docs/plan/`に置き、雛形は`docs/templates/`からコピーする。

## 段0 問いを立てる（`/kickoff`前半）

- AIが10問で人に聞く（選択肢付き、3回に分けて）
- 調査役が似たもの5〜10個を分解する（誰向け・核の体験・最初の10秒・強み・穴）
- 出力は企画メモ1枚（`docs/plan/plan-memo.md`）：誰に・何を・既存品との違い・賭け3つ・やめる条件
- 反対役を1回通し「作らないほうがよい理由」を企画メモに書き足す（受ける／退けるを1行ずつ）
- 次へ：人が賭け3つとやめる条件に合意した
- やめる：反対役の理由に反論できない／既存品で足りると分かった

## 段1 案を広げて選ぶ（`/kickoff`後半）

- AIが決まった切り口で20案（各5案）：競合の穴／他分野からの借用／制約を逆にする／観察した困りごと
- 人は2つずつ見比べて選ぶだけ。選んだ理由を好みの見本（`docs/plan/taste-samples.md`）に1行ずつ貯める
- 残った2〜3案は文書でなく動く試作（各半日目安）で比べる
- 次へ：試作を触って1案に決めた（決定ログへ1行）
- やめる：どの試作も段0の賭けを確かめる形にならない → 段0へ戻る

## 段2 いちばん小さい本物

- 最後まで通しで使える最小の1つだけ作る。同期・管理画面・重い検査は作らない
- 作る前に体験票（短縮版）で「あるべき瞬間」を書く
- 3人×5分、説明せず・聞かずに見る。観察ログへ1件3行
- 次へ：あるべき瞬間が3人中2人で起きる
- やめる：2回直しても起きない → 段1へ戻る（別案の試作）

## 段3 型を作る

- 作るもの：中身の型（体験票の完全版）・判断の手引き（`docs/plan/judgment-guide.md`）・機械の検査・AIの役割定義
- 検査と文書に使う労力は全体の3割まで。超えたら削る
- 数えられる判断（字数・件数・操作数・所要時間）はスクリプトにする。数えられない判断は手引きの問いと見本にする
- 上位モデルが使えるうちに手引きと見本を作り、通常運用は実装ティアで回せる形にする
- 次へ：手引きだけを渡した実装ティアで1件作り、及第点の問いに通った
- やめる：2週間で型が決まらない → 段2で件数を増やして観察し直す

## 段4 量産と見直し

- 1件ずつ：体験票 → 縦切り（1件を最後まで）→ 機械の検査と一目チェック（一目チェック役）→ 人の5分
- 週1回`/consult`で次の一手メモ（分かったこと／選択肢3つ（やらない含む）／推奨と理由）
- 上位モデルが使えるときは手引きと見本の見直しだけを頼む
- 続ける：人の5分で「あるべき瞬間」が起き続けている
- 戻る：同じ指摘が3件続く → 段3で手引きを直す／件数だけ増え観察ログが増えない → 量産を止める

## 配布の対象・対象外

- 配布（project-templateから同期・配布先で編集しない）：本ファイル、`docs/ai-consulting-rules.md`、`docs/templates/*.md`、`.claude/commands/{kickoff,consult}.md`、`.claude/agents/{devils-advocate,researcher,glance-check}.md`
- 対象外（各プロジェクトが所有・編集）：`docs/plan/`配下すべて（企画メモ・好みの見本・観察ログ・決定ログ・次の一手メモ・体験票・判断の手引き）
- プロジェクト固有の差は`docs/plan/`に書く。共通にすべき改善はproject-templateへIssue
- `sync-files.txt`にはファイル単位で列挙する（ディレクトリ指定は配布先の同名ディレクトリを丸ごと置き換え、独自のコマンド・エージェントを消すため）
