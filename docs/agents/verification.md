# 検証計画・手法（AI代理実機確認）

AGENTS.md「検証フェーズ」の補足。設計案に検証計画を書くとき、AI代理実機確認を設計・実施するときに読む。

- 検証計画：設計案に必ず含め、確認項目をAI担当／ユーザー担当／省略（理由付き）に三分する。ユーザー担当は人でなければ判定できない項目のみ（使い勝手、見た目、面白さ、体験の質）。動作・状態遷移・エラー処理・データ整合性・レイアウト崩れはAIが確認する。省略は手動確認が1分以内の目視で済み、かつ自動化に大がかりな環境構築が必要な場合のみ
- 手法：テストデータはAIが自作し、外部APIは`page.route`で固定レスポンスに差替（手順は`.claude/verify/README.md`）。判定はDOM（テキスト・属性・要素数・境界ボックス）で行い、スクリーンショットはユーザー確認用の保存物（AIが読むのはDOM判定不能かつ1〜2枚で足りる場合のみ）
- 完了報告：既存シナリオも再実行し、「AI確認済み（結果）」「ユーザー確認依頼（手順・該当画像）」を報告する
- 揺れの疑い（同じ条件で赤と緑が混ざる、まとめて赤で単独は緑など）がある時は、単独1回の緑を根拠にしない。同条件で3回以上回して判断する（#584・#621）。夜間E2Eは赤のシナリオを単独3回再実行し、Issueに「決定的／揺れ」を書く
