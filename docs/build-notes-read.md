# 作り方の記録：「めいれいを よむ」試作（Issue #723）

上位モデルがこの試作を作ったときの手順と判断を、別のモデル・別の機能でも同じ水準で再現できるように残す。新しい面の型・新しい画面を作るときに読む。判断の基準は `docs/design-playbook.md`（#737）。

## 1. 手順（この順で進める。飛ばさない）

## 2. 遊んで見つけた不足（動くのに及第点未満だった所）

動作確認のスクリプトは3件とも「成功」で通った。画像を見て初めて分かった。

1. **旗に「ゴール」の文字が出て、「よそう」の札と重なった**：ゴール旗の部品をそのまま使ったため。置いた旗は予想なので文字を消した
2. **縦画面で4手目が隠れた**：play の命令列は高さ72pxで縦スクロールする。読む面で命令が見えないのは致命的。高さの上限を外し、全部が同時に見えるようにした
3. **番号の札「1」が左上で切れた**：枠の内側の余白が足りなかった

共通点：どれも「既存部品を別の目的で使った所」で起きた。部品を流用したら、流用先の目的（ここでは「読む」）で1回ずつ見直す。

## 3. 判断の記録（なぜそうしたか）

- **外したら命令列を替える**：同じ命令列のままだと、「けっか」の場所へ旗を置き直すだけで通れる（総当たり2回）。3本を順に回し、止まるマスが互いに違うことを検査で保証した
- **外した直後は、古い命令列と足あとを残す**：「ためしなおす」を押すまで替えない。ここが、ずれた手を見つける時間になる
- **指の見本は、答えのマスを指さない**：ロボットから1手ぶんだけなぞる（1手目は命令の先頭を見れば分かる）。操作は見せるが、止まるマスは見せない
- **問いの文は全面同じ**：「ロボットは どこで とまる？」。面ごとの違いは盤面と命令列で出す
- **3面の役割**：であう（4手・壁なし）→つかう（6〜7手・途中で戻る向きがある）→ひねる（氷。数えた場所で止まらない）。3面目は、氷を知らない素直な答えが必ず外れる
- **1コマ実行は付けない**：1手ずつ進めると、考えずに答えが出る
- **点数・回数は出さない**。外した回数も画面に出さない

## 3b. 2回目の磨き（「動く」から「考えが見える」へ）

1回目は「止まるマスを当てる」だけで、外したときに分かるのは結果の場所だけだった。2回目は、子どもの考えそのものを画面に残す形にした。考え方は次の順。

1. **この面で子どもの頭の中にあるものは何か**を書く → 「1手ずつ動かした道」
2. **それを操作にする** → ロボットから指でなぞると、通ると思ったマスに輪が残る。旗は最後のマスに立つ（タップで旗だけ置く方法も残す）
3. **結果を、考えと同じ形で返す** → 実行するとロボットの足あとが輪の中に入っていく。合っていれば輪が埋まり、ずれた先は空の輪と、輪の無い足あとに分かれる
4. **ずれの原因を、事実として指す** → 最後に同じだったマスと、その次の手を出した命令が光る（「ここで みちが わかれたよ」）。正しい道は言わない。足あとが残っているだけ
5. **覚えておく負担を道具に移す** → 命令をタップすると「ここまで よんだ」の印が付く（答えには関わらない）
6. **組む場所と読む場所を見た目で分ける** → 命令は紙の札（目の絵つき）。木のトレイ・×・追加ボタンは出さない。旗は「はた立て」に置いてあり、置くと薄くなる（文で説明しない）

氷の面では、この形が効く。数えたとおりになぞると輪は氷の上で曲がるが、足あとは氷の端まで続く。分かれたマスが氷の上になり、「みぎ」の命令が光る。

見た目で直した点：旗のマスには輪を重ねない／指の見本は、ロボットから1手ぶんだけなぞる（止まるマスは指さない）。

## 4. 残したこと（人が決める・次に作る）

- この形が #104（予想の選択肢UIの全廃）の範囲内か。選択肢はなく、盤面に旗を置く
- 8面への拡張（クッション・スイッチ・かぎ）。3本とも止まるマスが違う盤を作る必要がある
- 導入の見本は既存のデモ（命令どおりに動いて旗で止まる）を使った。なぞる操作の見本は1面目の指だけ
- なぞる操作が実機の指で気持ちよく動くか（マスが小さい盤・縦360px）は未確認
- 縦360pxで失敗の吹き出しの文が横に流れる（既存の挙動。#744）
- E2E は未作成（試作のため）。公開するときに流れ1本を足す
- 実機で見る3点：1面目で最初の操作まで10秒以内か／氷の面で手が止まるか／外した後に命令列と足あとを見比べているか

## 5. 別の機能で同じ水準を出すための確認（7つ）

1. 体験の3行（目標・あるべき瞬間・わるい例）を、実装の前に書いたか
2. わるい例を、検査かデータの形で防いだか（文で注意しただけになっていないか）
3. 素直な手・総当たりで何が起きるかを、実際に操作して確かめたか
4. 横と縦の2つの大きさで、失敗した直後の画面を自分の目で見たか
5. 流用した部品を、流用先の目的で1つずつ見直したか
6. 見本・ヒントが答えを指していないか
6b. 子どもの考え（途中の道・順番・理由）が画面に残り、結果がそれと同じ形で返るか（3b章）
7. 残したことと、人が実機で見る点を書いたか
