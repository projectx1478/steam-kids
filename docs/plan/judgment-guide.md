# 設計の手引き（design-playbook）

レッスン・面・画面を考えるとき、起票するとき、設計を点検するときに読む。上位モデルが使えない時期でも同じ質の判断ができるよう、判断を「決まった問いに答える」形にしてある。原則の正本は PROJECT.md。ここは使い方。

## 1. 面の及第点（5つの問い）

面（play 1つ）ごとに、次の5つに1文ずつ答える。1つでも答えられなければ、その面は作り直す。

1. **気づき**：この面をクリアした子は、何に気づくか（「〜すると〜になる」の形。形容詞は書かない）
2. **素直な手**：何も考えずにいちばん目につく手を打つと、何が起きるか（クリアできるなら、この面は「であう・つかう」以外に置けない）
3. **総当たり**：考えずに端から試すと、何回でクリアできるか（後半の面で6回以内なら作り直す）
4. **前との違い**：直前の面と、考えることの何が違うか（「長くなった」「数が増えた」だけは違いに数えない）
5. **手がかり**：失敗したとき、画面のどこを見れば次の手が分かるか（文でなく、盤面に残る事実で答える）

## 2. ひねりの型（14種）

「ひねる」「まぜる」の面は、次の型から1つ選んで作る。同じ型を1レッスンで2回使わない。新しい型を見つけたら、ここに足す。

| 型 | 中身 | 例 |
|---|---|---|
| 1 行きすぎる | 素直に進むと止まれない・通りすぎる。手前で別の手を打つ | 氷の列の途中にゴール |
| 2 もどる | 一度通った所へもう一度来る必要がある | かぎを取ってから来た道を戻る |
| 3 順番が逆 | 近いものから取ると詰む。遠いものが先 | 遠いスイッチを先に踏む |
| 4 じゃまを使う | これまで障害だったものが道具になる | クッション・壁を止め具に使う |
| 5 やらないが正解 | 取れるもの・押せるものに、触らないほうがよいものがある | 閉じるスイッチをよける |
| 6 ひとつで2役 | 1つの操作が2つの結果を同時に起こす | 1つのスイッチが開く壁と閉じる壁 |
| 7 道具をへらす | 使える命令・道具を1つ減らす（上限でなく種類で制約） | 「ひだり」なしで左のゴールへ |
| 8 待つ | 動かない・遠回りすることで時機を合わせる | 周期ドアが開く歩数に合わせる |
| 9 逆から考える | ゴール側からたどると道が1本に決まる | ゴールの手前が氷で、入り口が1つ |
| 10 同じ手で2つ | 1つの命令列・置き方で、2つの盤・2つの条件を満たす | ふたつの へや |
| 11 見た目と中身 | 同じに見えるものの働きが違う。試して見分ける | ？の はこ、色の違うかぎ |
| 12 ぜんぶ見つける | 答えが複数あり、全部ならべると規則が見える | つりあう置き方を3組 |
| 13 直す | できあがった誤りを読んで、1か所だけ変える | 12手の列の誤り1つ |
| 14 作る側 | 条件を満たす盤面・並びを自分で作る | とおまわり めいろ |

## 3. 見本（よい面・わるい面）

判断に迷ったら、ここと比べる。新しい判断をしたら1行足す（20行まで。超えたら古いものと入れ替える）。

| 面 | 判定 | 理由 |
|---|---|---|
| cmd-01 p1〜p3（3×3〜5×5、別解66〜177本） | であう面としては可。後半面としては不可 | 見えている道を矢印に写せば通る。p2・p3 は p1 と考えることが同じ（問4に答えられない） |
| cmd-03 p1・p2（誤った列を直す、別解1本） | 可 | 列を読まないと直せない。型13。素直な手（そのまま実行）は失敗し、止まった命令が手がかりになる |
| ice-01 の「まっすぐ行くと通りすぎる」面 | 可 | 型1。素直な手が失敗し、止まったマスが手がかり |
| ice-01 intro「こおりの うえは すべるよ」 | 不可 | 規則を先に言っている。問い（「こおりの うえは どうなる？」）に替える |
| switch-02 intro「スイッチは ぜんぶ ふもう」 | 不可 | 攻略法そのもの |
| key-01（intro と summary が同じ文） | 不可 | 体験の前後で言うことが変わらない＝気づきが無い |
| teko-01〜03（置く目盛りを1つ選ぶ、候補4〜6） | 前半2面まで可。それ以降は不可 | 総当たり6回以内。傾きを見て1つ動かせば着く |
| 浮力の `find`（ぴたりを2組見つける） | 可 | 型12。1組目を覚えても2組目は別 |
| sort-01 p1・p2（3枚、6通り） | であう面としてのみ可 | 総当たり6回 |
| 20手に伸ばしただけの後半面 | 不可 | 「長くなった」は違いに数えない |
| cmd-08 の2回目（道をなぞり、足あとが輪に入る） | 可 | 考えを画面に残し、結果を同じ形で返す。外したとき、ずれた手が盤面の事実で分かる（docs/build-notes-read.md 3b章） |

## 4. アイデアの出し方（レッスン・面）

思いつきを並べない。次の順で出し、ふるいにかける。

1. **気づきから書く**：「〜すると〜になる」を先に1文で書く。盤面はその後。気づきが書けない案は出さない
2. **表を埋める**：縦に概念（その単元で学ぶこと）、横に問いの向き（すすめる・なおす・よむ・さがす・つくる）を置き、空いているマスから案を出す。同じマスに3面以上あるなら、そのマスにはもう足さない
3. **型を当てる**：2章の14種を順に当て、「この概念で型Nをやるとどうなるか」を1行ずつ書く。成り立たない型は飛ばす
4. **10個出して2個残す**：1章の5つの問いに答えられない案を落とす。残った案を、既存のいちばん近い面と並べ、違いを1文で書けないものを落とす
5. **最初の10秒を書く**：残った案について、説明なしで最初の操作まで行ける理由を、画面にあるものだけで書く。書けなければ「であう面」を前に1つ足す
6. **試作は1面**：JSON 1枚で作れるなら文書で比べず、作って遊ぶ

## 5. 起票と点検で、やりがちな失敗

- 完了条件に床（収まる・通る・48px）しか書かない → 「あるべき瞬間」と「わるい例」を1行ずつ必ず書く
- わるい例を一般論で書く → 「手間の少ない実装がやりそうなこと」を具体的に1つ書く（例：数字を出さず絵だけにする）
- 「分かりやすくする」「楽しくする」と書く → 画面で起きることに書き直す
- 評価役が「改修が大きいのでやらない」と落とす → 落とす理由が手間だけなら、人に回す
- 文言で解決する → 先に絵・動き・盤面で解決できないかを考える。文は最後

## 6. 上位モデルが使えないときの運用

- 設計の点検は、書いた役と別の役が、1章の5つの問いと5章だけを見て行う（設計全文を読ませない）
- 2つの役の答えが食い違った問い、どちらも答えられなかった問いだけを、人に回す
- 迷った判断は3章に1行足してから進める。次に同じ迷いが出たら、3章の行に従う
- 月に1回、3章と2章を読み返し、当たらなくなった行を消す

## 7. 導線の原則（画面・遷移を足す・変えるとき）

1. **2タップで遊べる**：2回目以降の起動から、前回の続きの面までのタップは2回以内。1つしか選べない画面は出さない
2. **家は1つ**：戻る先はいつも単元マップ。「おわる」「もどる」「🏠」の行き先を分けない
3. **何も失わない**：作りかけの命令列・置き方は、リロード・戻る・中断でも残す。消すのは子どもが「ぜんぶけす」を押したときだけ
4. **端末の戻る＝1つ前の画面**：どの画面でも、アプリの外へ出ない。リロードは今の面に戻る
5. **主の出口は1つ**：1画面に主ボタン（青・大）は1つ。ほかは小さく、2つまで
6. **同じことは同じ言葉・同じ場所**：やり直す・ためす・設定は、全教材型で1語・1か所
7. **押せないものは理由を返す**：錠・無効のボタンも押すと、開け方を絵か1文で返す。無反応にしない
8. **待たせるのは初回だけ**：同じ命令列の2回目以降の実行は速くできる。演出の待ちは1秒以内
9. **行き止まりを作らない**：どの画面にも、家へ戻る手段が1つ見えている（保護者画面・読み込み失敗を含む）
10. **つながらなくても同じ**：一度開いた端末では、オフラインでも全画面・全公開レッスンが開く
