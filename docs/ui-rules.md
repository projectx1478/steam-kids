# UI規則

UI規則（受け入れ条件。すべて判定可能な数値条件とする）:

- 1レッスン = 4〜7ステップ、所要5分（長尺試作のみ、最大12ステップ・所要約8分（仮））
- 1画面の文章は20字以内
- アニメーションは1手あたり0.6秒。実行中は該当箇所をハイライト
- 否定の表示・否定語は使わない。未達成時は前向きな反応と、どこを直すかのヒントを出す（Issue #91）。
  盤面を0.5秒やさしくゆらし（reduced-motion時は枠を0.5秒光らせる静止表示）、罰則音ではない
  低音スイープの効果音（`tryAgain`）を鳴らして気づかせる。「ためしなおす」以外の操作ボタン・
  命令チップの取り消しは失敗中は押せないままとし、「ためしなおす」を押すと編集できる（命令列は残る）
  （なおす系も含め全レッスン共通。Issue #106）
- 命令の追加はタップまたはドラッグで行う（ドラッグは命令列の最も近い隙間（先頭・途中・末尾）へのドロップ。上限と止まった前部には入れない）
- タップ領域は64px四方以上（保護者ダッシュボードは対象外）
- 操作画面（play・れんしゅう）は横向きで「盤面｜操作パネル」の左右分割（パネル幅320px、セル上限120px、`#app`の幅制限なし）、縦向きは縦積み（セル上限64px）。命令パレットは全ステージ（チュートリアル含む）・全向きで WASD 配置の2行×3列（上段 [とめる][うえ][空き]・下段 [ひだり][した][みぎ]。tutorial だけ上段右に⚙。「とめる」は maxPauses>0 のときだけで、0 なら左上は空きマス。「とめる」には残り回数（✋・とめる・×N）を1ボタンに統合。⚙＝`button[data-action="menu"]`〔aria-label「せってい」。play は吹き出し欄の右端、tutorial はパレット上段右〕は実行中・ロック中・指ガイド中も押せる。旧配置は破棄。Issue #395・#467）。play（シーソー除く）とれんしゅうはヘッダ（←・🏠・単元名・区分チップ・⚙）とステップ点列を出さず、「いまの ばしょ」（単元名・区分チップ・点列）と「レッスンせんたくがめん」（まえは廃止。前のステップへは端末の戻る）は ⚙ のメニュー（画面中央のパネル）に入れる。はじめ・まとめ・シーソー・予想・たね選び・選択画面は従来のヘッダ・点列。メニューの「がめん」（24px未満の盤のみ）を押すと画面下のズームバー（おおきく／ちいさく／ぜんぶみる／もどる）に移り、盤面を見ながら倍率を調節できる（Issue #467）。背の低い横向き（高さ700px以下）は操作ボタンを1行4列にする。ただし操作ボタン行（play・れんしゅうの `.sk-screen-actions`）は高さ480〜700pxの横向き［1024×600等］では2×2、それより低い横向きは4列（Issue #156・#370。`l1-split-layout`）
- play中にレッスンせんたくがめんへ離れる操作（⚙の「レッスンせんたくがめん」・🏠・端末の戻る）には、常に離れる確認を置く（`js/ui-dialog.js` の `confirmDialog`。「プレイを つづける」を大きく上、「もどる」を小さく下に離して置く。覆いのタップ＝つづける。`window.confirm`は使わない）。ほごしゃの画面を開く前の確認も同じ部品。play以外の画面遷移と、リセット系の操作（ひとつ けす・ぜんぶ けす・チップ×）には確認を置かず、Undoで戻せるようにする。命令列の下書き保持（←で戻って再び進むと復元される。レッスン内のみ・メモリのみで保持しクリア時に消える）も併用する（Issue #542）
- 文字はひらがな主体。漢字は`{漢字|よみ}`のルビ記法で書き、文部科学省「学年別漢字配当表」
  （`js/kanji-grades.js`）内の漢字に限る。表示は端末内の「よみレベル」設定に応じて
  漢字/ひらがなを自動で出し分け、ふりがなトグルで`<ruby>`表示を切り替える（Issue #59）
- 音声読み上げはMVP対象外。文言はレッスンデータ側の文字列として持ち、DOMに直書きしない
- 新ルール初登場時（各レッスンで新しい操作が初登場する時）はなぞり操作型チュートリアルを置く。手順は文章でなく
  実物ボタンと同じ見た目のお手本列・光るボタンで示す。結果は図（番号付きゴースト矢印）を主とし、
  20字以内の1行キャプションを添える（Issue #81・#93）
- 予想・実行ステップは操作画面へ直接入る（課題カード・やりかた帯はIssue #97で廃止）。
  操作画面には盤面・操作ボタン・命令列と、小鳥の吹き出しの問い文だけを置く（問い文の行は撤去。鍵トレイ・残数・塗りの見本があるレッスンだけ補助行が残る）。説明は「れんしゅう」
  （なぞり操作型チュートリアル）と指ガイドで行う。8秒操作が無ければ実物ボタンを3秒だけ
  光らせる（1ステップ最大2回。Issue #89）
- 実行結果（やったね／ヒント）は小鳥の吹き出しで出す。自動では消さず、顔か吹き出しのタップ、
  または次の結果・ヒントで置き換わる（`js/ui-bird.js`・`js/ui-reaction.js`）。クリア時の「つぎへ・ためしなおす」は
  操作パネルのボタン行に表示し、押すまで消えない（Issue #97）。失敗後の「ためしなおす」は
  命令列を残して編集可にする。クリア後の「ためしなおす」は命令列をリセットする（なおす系は初期の「ずれた」列に戻す）
- 「はじめに」画面では、ロボットが正解の道をたどってゴールへ到達する完成イメージを
  アニメーションで1回だけ自動再生し見せる（本番のplayとは別のstart/goalを使い、答えの
  ネタバレを避ける。reduced-motion時も1手0.6秒のコマ送りで動かし、静止画にはしない。
  レッスンで新しく出てくる要素（命令チップ・まとめ・なおす・item）へ焦点を当てる。
  `lessons/*.json`の`intro.demo`・`js/ui-demo.js`のrenderGoalDemo。Issue #97・#104）。
  初回自動再生の直前だけ盤面に「よーい…」を1秒表示し、`start`音の後に再生する
  （「おてほんを みる」は待たない。Issue #107）
- 起動時（`?lesson=`・`?view=map`のどちらも無い時）のみタイトル画面（`js/ui-title.js`）を
  1回はさむ。「STEAM KIDS」の文字はロゴ表記としてひらがな主体規則の例外とする（Issue #107）
- レッスン選択画面のクリア済みボタンは色（`bg-emerald-500`）＋金色★バッジで示し、
  重ねた赤チェックは使わない（単元進捗ドットの赤チェックはIssue #58のまま維持。Issue #107）
- `grid-runtime`のplayは2〜4ステージ（p1, p2…。長尺試作は最大8）で構成し、後のステージほど最短手数
  （まとめ命令ありはチップ数）を非減少にして難易度を上げる。壁にぶつかった手が1つでも
  あれば結果としてゴールに着いても正解にしない。途中ステージのクリアは`stage_clear`
  イベントのみを記録し、最終ステージのクリアだけがレッスン全体の`clear`・単元スタンプの
  対象になる（Issue #104）
- ステップ進行はロードマップ表示（区分アイコン付きノード＋接続線）にし、クリア済みレッスンでは
  playの各ステージのノードがボタン化してタップで直接移動できる（Issue #104）
- クリアの演出はステージクリア＜レッスンクリア＜単元ぜんぶクリアの3段階で大きくする
  （紙ふぶき60/120/200粒、効果音fanfare→lessonClear→grandFanfare（Issue #268）、単元ぜんぶクリアのみメダル表示。
  reduced-motion時は拡大した静止表示＋効果音のみ。Issue #104）。
  単元ぜんぶクリアの初回のみ、ロボットが目を閉じた「おつかれさま」を添える（離れてよい合図。
  強制・催促・連続記録は使わない。Issue #267）
- タップ領域の64px基準に対する例外（48px）：ダッシュボードの開発者用リンク（dashboard.html:72）、
  開発者画面（dev=1）からの戻りリンク（js/ui-picker.js）。位置（目立たない場所）と色（地味）で
  保護者・開発者向けであることを示す（Issue #257）
- 命令を並べる場所は凹み枠のトレイ（`.command-tray`）とし、末尾に「次に置く」空き枠
  （`.tray-slot`。1個目は←矢印・2個目以降は番号）を1つだけ表示する（Issue #110）
- 不正解時は盤面のマス（`view.dim`）だけを暗くし、印・ロボットは暗くしない。「ためしなおす」で
  盤面を作り直した直後はロボットがポンと現れ（`view.popIn`）、「スタート！」は
  ステージ開始時だけ盤面中央へ2秒表示する（再開では出さない。盤面の最初の操作〔命令・◀▶・−＋・ためす・キー・ドラッグ〕で消える。←もどる・⚙・小鳥の顔では消えない。表示が消えてから問い文の吹き出しを出す。Issue #497・#635）
- 文字は丸ゴシック体（教育漢字1026字＋かな・記号のみの自前ホストWOFF2サブセット。
  `fonts/mplusrounded1c-800.woff2`）を使う。Google Fonts等の外部読み込みは行わない（Issue #110）
- playの操作ボタン行に「👣 1コマ」（`data-action="step"`・64px以上）を置き、タップごとに命令を
  1つずつ実行できる。今動いている命令のチップは黄色の強調（`ring-4 ring-yellow-400`）で示し、
  じっこうの一括実行でも同じ強調を使う。1コマ実行の途中で「▶ じっこう」を押すと残りを自動で
  進め、最後の1手まで進めるとじっこうと同じ判定（clear／stage_clear／失敗時のロック）になる
  （Issue #111）

## 学習体験の判定表（DO / DON'T。Issue #154）

PROJECT.md「学習体験の固定仕様」の3原則を実装で判断するときの基準。

| 項目 | 採用する（DO） | 避ける（DON'T） |
| --- | --- | --- |
| 説明・ガイド | 指アイコンのアニメーション、ターゲット枠の点滅 | 「〇〇してね」等のテキストモーダル、説明のための確認ダイアログ（離れる確認は16行目の方針で置く） |
| 失敗の反応 | 壁で即時ストップ、やさしい横揺れ、トレイの該当チップ強調、短い事実の文 | 「ざんねん」等の評価の言葉、大きな✕、罰則音 |
| 成功の反応 | ロボットのダンス・ジャンプ、星・紙吹雪、効果音、完了スタンプ | 「100点」等の点数・正誤テキスト |
| ヒント | ぶつかったマスの強調、塗り残しのパルス表示 | 正解の道のゴースト表示、正解の命令順の提示 |

計画型の失敗時に盤面を暗くする演出（`view.dim`）は答えを見せないため可。チュートリアル（れんしゅう）の予定の道の表示は操作練習であり「正解の道の提示」に当たらない。

失敗時の短い事実の文の線引き（Issue #255）：「盤面で起きたこと」の文は可。「次にどうするか」の
指示は不可。つまずきが次の手がかりになる（原則3）ため、答えや次の手の指示は見せない。
例：「ゴールの てまえで とまったよ」は可。「みぎに 1つ たそう」は不可。
- play のクリア後の間・結果ダイアログ中も、吹き出し欄の ⚙（`[data-action="menu"]`。#574 段Cで欄へ移動）だけは押せる（`ui-clear.js` の `lockScreen` が ⚙ の祖先を避けて兄弟だけを inert にし、⚙ をダイアログ手前の z-20 に出す）。まえ／えらぶ へ出られる（Issue #467）。

## 画面設計の5原則

番号が優先順。PR は【自動】と【判断】の項目を満たす。【実機】は人が実機で確かめる。

### 1. 努力を守る
プレイ中の誤操作で、組んだ命令や進み具合が失われない。
- プレイ画面を離れる操作には、ブロックの有無にかかわらず確認が出る。【自動】
- 確認ダイアログでは、続ける側を目立たせ、離れる側と離して置く。【自動＋実機】
- よく押すボタンのすぐ隣に、失うボタンを置かない。【自動】

### 2. 押したらすぐ手応えがある
すべての操作に、すぐ音か見た目の反応がある。いまの状態（組んでいる、動いている、成功、失敗）が常に分かる。
- 押せるボタンにはすべてクリック SE が鳴る。【自動】
- BGM は画面と対応表で決まり、どの経路で来ても同じ曲が鳴る（ためしなおす の後も含む）。【自動】
- 成功・失敗のたびに専用の音と表示がある。【自動】

### 3. 押す前に結果が分かる
ボタンの文言や絵から、押した後に何が起きるか、どこへ行くかが分かる。迷う要素を足さない。
- 確認ダイアログの問いには、実際の行き先や結果の名前が入っている。【自動】
- 同じ文言のボタンは、どの画面でも同じ結果になる。「まえの」のように行き先が場面で変わる言葉を単独で使わない。【自動】
- 同じ画面に、同じ結果をもたらすボタンや導線は1つだけ。【自動】
- その場で操作につながらない表示は、削るか奥へしまう（例：クレジットはボタンを押してから）。【自動＋判断】
- 設定、チュートリアル、ダイアログなど、似た画面は同じ部品と配置を使い、違うのは中身の差分だけ。【自動】

**文言と結果の対応**（Issue #554）。同じ結果になるボタンは同じ文言、別の結果には別の文言を使う。

| 文言 | 出る条件 | 行き先 |
|---|---|---|
| ▶ おてほんを みる | デモがある単元の intro | デモをもう一度流す |
| ↺ ためしなおす | 失敗した直後 | 同じステージの組みなおし |
| ためしなおす | クリア後の結果 | 同じステージのやり直し |
| もういちど よそう | predict 単元 | 予想をやり直す |

「ためしなおす」を失敗後とクリア後の2経路で使うのは、どちらも同じステージへ戻る操作として同じ文言にする。違いは命令列だけ（失敗後は残る、クリア後は消える）。

**intro の構成規則**（Issue #554）。主ボタンは常に右端にあり、デモがあれば再生ボタン、tutorial があれば「そうさほうほう」を足す。無いボタンは詰めて右寄せのまま空けない。teko など、デモが要らない単元は今のままでよい。ギミックごとの1本目レッスンの構成（`g3-intro-wording`で検証）：

| ギミック | 1本目 | 再生ボタン | そうさほうほう | 主ボタン |
|---|---|---|---|---|
| 命令のみ | cmd-01-susumu | あり | あり | はじめる |
| items | donguri-01-hirou | あり | あり | はじめる |
| ice | ice-01-suberu | あり | あり | はじめる |
| cushion | ice-02-kabe | あり | なし | はじめる |
| keys | key-01-kagi | あり | あり | はじめる |
| switches | switch-01-suicchi | あり | あり | はじめる |
| paint | paint-01-nuru | あり | なし | はじめる |
| periodic | switch-07-shuuki-door | あり | なし | はじめる |
| teko（対照） | teko-01-tsuriai | なし | なし | はじめる |

### 4. 盤面と命令を隠さない
遊びの中心（命令を組む → うごかす → 結果を見る → なおす）を、ほかの表示がさえぎらない。
- 吹き出し、メニュー、通知が、盤面と命令列に重ならない。【自動】
- 例外：返事を求める表示（⚙メニュー・確認ダイアログ・クリアの結果）は、開いている間だけ覆ってよい。失敗時の表示・ヒント・吹き出し・指ガイドは例外にしない。
- 例外：start-cue（ステージ開始時の「スタート！」。2秒か最初の操作で消える・タップ素通し）は盤面内表示の例外とし、盤面の上に重ねてよい。
- 360×640、低い横向き（844×390 など）、1024×600 で、操作に必要な部品がすべて画面に収まる。タップできる部品は 64px 以上。【自動】
- 保護者画面は 64px の対象外（大人向け）。ただし画面外に出て届かないボタンは直す。入力欄の高さはそろえない。
- 失敗から組みなおしまで、最小のタップで戻れる。【自動】

### 5. 失敗しても安心できる
失敗を罰にせず、どこで違ったかが分かる手がかりにする。
- 失敗時の音と表示が、責めたり怖がらせたりしない。【実機】
- 失敗の後、どの命令で違ったかが分かる。【自動】
- 失敗の回数を責める表示がない。【自動】
