# UI規則

UI規則（受け入れ条件。すべて判定可能な数値条件とする）:

- 1レッスン = 4〜7ステップ、所要5分
- 1画面の文章は20字以内
- アニメーションは1手あたり0.6秒。実行中は該当箇所をハイライト
- 否定の表示・否定語は使わない。未達成時は前向きな反応と、どこを直すかのヒントを出す（Issue #91）。
  盤面を0.5秒やさしくゆらし（reduced-motion時は枠を0.5秒光らせる静止表示）、罰則音ではない
  低音スイープの効果音（`tryAgain`）を鳴らして気づかせる。「もういちど」以外の操作ボタン・
  命令チップの取り消しは押せない状態にし、「もういちど」で命令列をリセットするまで解除しない
  （なおす系も含め全レッスン共通。Issue #106）
- 命令の追加はタップまたはドラッグで行う（ドラッグは命令列の末尾へのドロップのみ。途中への挿入はしない）
- タップ領域は64px四方以上（保護者ダッシュボードは対象外）
- 操作画面（play・れんしゅう）は横向きで「盤面｜操作パネル」の左右分割（パネル幅320px、セル上限120px、`#app`の幅制限なし）、縦向きは縦積み（セル上限64px）。背の低い横向き（高さ700px以下）はパレット・操作ボタンを1行4列にする（Issue #156。`l1-split-layout`）
- 画面遷移・リセットの確認ダイアログは置かない（`window.confirm`も使わない）。誤操作の保険は
  Undo（ひとつ けす・ぜんぶ けす・チップ×）と、playの命令列の下書き保持（←で戻って
  再び進むと復元される。レッスン内のみ・メモリのみで保持しクリア時に消える）で行う
- 文字はひらがな主体。漢字は`{漢字|よみ}`のルビ記法で書き、文部科学省「学年別漢字配当表」
  （`js/kanji-grades.js`）内の漢字に限る。表示は端末内の「よみレベル」設定に応じて
  漢字/ひらがなを自動で出し分け、ふりがなトグルで`<ruby>`表示を切り替える（Issue #59）
- 音声読み上げはMVP対象外。文言はレッスンデータ側の文字列として持ち、DOMに直書きしない
- 新ルール初登場時（各レッスンで新しい操作が初登場する時）はなぞり操作型チュートリアルを置く。手順は文章でなく
  実物ボタンと同じ見た目のお手本列・光るボタンで示す。結果は図（番号付きゴースト矢印）を主とし、
  20字以内の1行キャプションを添える（Issue #81・#93）
- 予想・実行ステップは操作画面へ直接入る（課題カード・やりかた帯はIssue #97で廃止）。
  操作画面には盤面・操作ボタン・命令列と1行の問い文だけを置く。説明は「れんしゅう」
  （なぞり操作型チュートリアル）と指ガイドで行う。8秒操作が無ければ実物ボタンを3秒だけ
  光らせる（1ステップ最大2回。Issue #89）
- 実行結果（やったね／ヒント）は盤面に重ねず、問い文と同じ場所へ3秒だけトースト表示し、
  その後は問い文へ自動で戻る（`js/ui-toast.js`）。クリア時の「つぎへ・もういちど」は
  操作パネルのボタン行に表示し、押すまで消えない（Issue #97）。「もういちど」は正解・不正解に
  関わらず命令列を必ずリセットする（なおす系は初期の「ずれた」列に戻す。Issue #104）
- 「はじめに」画面では、ロボットが正解の道をたどってゴールへ到達する完成イメージを
  アニメーションで1回だけ自動再生し見せる（本番のplayとは別のstart/goalを使い、答えの
  ネタバレを避ける。reduced-motion時も1手0.6秒のコマ送りで動かし、静止画にはしない。
  レッスンで新しく出てくる要素（命令チップ・まとめ・なおす・item）へ焦点を当てる。
  `lessons/*.json`の`intro.demo`・`js/ui-demo.js`のrenderGoalDemo。Issue #97・#104）。
  初回自動再生の直前だけ盤面に「よーい…」を1秒表示し、`start`音の後に再生する
  （「もういちど みる」は待たない。Issue #107）
- 起動時（`?lesson=`・`?view=map`のどちらも無い時）のみタイトル画面（`js/ui-title.js`）を
  1回はさむ。「STEAM KIDS」の文字はロゴ表記としてひらがな主体規則の例外とする（Issue #107）
- レッスン選択画面のクリア済みボタンは色（`bg-emerald-500`）＋金色★バッジで示し、
  重ねた赤チェックは使わない（単元進捗ドットの赤チェックはIssue #58のまま維持。Issue #107）
- `grid-runtime`のplayは2〜4ステージ（p1, p2…）で構成し、後のステージほど最短手数
  （まとめ命令ありはチップ数）を非減少にして難易度を上げる。壁にぶつかった手が1つでも
  あれば結果としてゴールに着いても正解にしない。途中ステージのクリアは`stage_clear`
  イベントのみを記録し、最終ステージのクリアだけがレッスン全体の`clear`・単元スタンプの
  対象になる（Issue #104）
- ステップ進行はロードマップ表示（区分アイコン付きノード＋接続線）にし、クリア済みレッスンでは
  playの各ステージのノードがボタン化してタップで直接移動できる（Issue #104）
- クリアの演出はステージクリア＜レッスンクリア＜単元ぜんぶクリアの3段階で大きくする
  （紙ふぶき60/120/200粒、効果音clear→fanfare→grandFanfare、単元ぜんぶクリアのみメダル表示。
  reduced-motion時は拡大した静止表示＋効果音のみ。Issue #104）
- 命令を並べる場所は凹み枠のトレイ（`.command-tray`）とし、末尾に「次に置く」空き枠
  （`.tray-slot`。1個目は←矢印・2個目以降は番号）を1つだけ表示する（Issue #110）
- 不正解時は盤面のマス（`view.dim`）だけを暗くし、印・ロボットは暗くしない。「もういちど」で
  盤面を作り直した直後はロボットがポンと現れ（`view.popIn`）、問い文の場所へ「スタート！」を
  1秒だけ表示して再スタート状態を伝える（失敗リザルト状態との違いを明確にする。Issue #110）
- 文字は丸ゴシック体（教育漢字1026字＋かな・記号のみの自前ホストWOFF2サブセット。
  `fonts/mplusrounded1c-800.woff2`）を使う。Google Fonts等の外部読み込みは行わない（Issue #110）
- playの操作ボタン行に「👣 1コマ」（`data-action="step"`・64px以上）を置き、タップごとに命令を
  1つずつ実行できる。今動いている命令のチップは黄色の強調（`ring-4 ring-yellow-400`）で示し、
  じっこうの一括実行でも同じ強調を使う。1コマ実行の途中で「▶ じっこう」を押すと残りを自動で
  進め、最後の1手まで進めるとじっこうと同じ判定（clear／stage_clear／失敗時のロック）になる
  （Issue #111）

## 学習体験の判定表（DO / DON'T。Issue #154）

PROJECT.md「学習体験の固定仕様」の3原則を実装で判断するときの基準。

| 項目 | 採用する（DO） | 避ける（DON'T） |
| --- | --- | --- |
| 説明・ガイド | 指アイコンのアニメーション、ターゲット枠の点滅 | 「〇〇してね」等のテキストモーダル、確認ダイアログ |
| 失敗の反応 | 壁で即時ストップ、やさしい横揺れ、トレイの該当チップ強調、短い事実の文 | 「ざんねん」等の評価の言葉、大きな✕、罰則音 |
| 成功の反応 | ロボットのダンス・ジャンプ、星・紙吹雪、効果音、完了スタンプ | 「100点」等の点数・正誤テキスト |
| ヒント | ぶつかったマスの強調、塗り残しのパルス表示 | 正解の道のゴースト表示、正解の命令順の提示 |

計画型の失敗時に盤面を暗くする演出（`view.dim`）は答えを見せないため可。チュートリアル（れんしゅう）の予定の道の表示は操作練習であり「正解の道の提示」に当たらない。
