# 教材型と grid-runtime 仕様

教材型を実装するとき、レッスンを追加するときに読む。
全教材に共通する3原則と2つの操作モデル（計画型／直接操作型）は PROJECT.md「学習体験の固定仕様」、UI規則は `docs/ui-rules.md`。

## 教材型

エンジンが持つ操作部品。**型は5つで打ち止めとし、以降はJSONで表現する。**

| ID | 型 | 想定単元 |
| --- | --- | --- |
| `grid-runtime` | グリッド上を命令で動かす | プログラミング、方向、座標 |
| `predict-slider` | 連続量を動かして結果を予想 | てこ、電流、濃度、比例、速さ |
| `sort-order` | 仕分け・並べ替え | 分類、手順、時系列 |
| `connect` | つなぐ | 回路、食物連鎖、対応関係 |
| `build` | くみたて | 実験の条件設計、式づくり |

MVP実装対象は `grid-runtime`。予想ステップ（`kind: "predict"`）は将来の教材型向けに語彙・実装
（`js/ui-predict.js`）のみ残し、現行レッスンでは使わない（Issue #104でよそうの選択肢UIを全廃）。

## grid-runtime 仕様

- 命令は**画面の絶対方向4種**（うえ・した・みぎ・ひだり）。ロボットの向きは見た目のみ（最後に進んだ方向を向く。クリア時は正面）で、命令の意味は変わらない（Issue #146）
- 命令の追加・削除はタップ。個別削除（×）と全消しの2つを用意する
- 実行は1手0.6秒。実行中の命令をハイライトする
- 座標は y が下向きに増加する（`up` は y−1、`down` は y+1）
- 壁・盤外に進もうとした手はその場で停止する。**失敗表示は出さない**
- 壁・盤外にぶつかったらその手で実行を止める（残りの手は再生しない。Issue #136）。こおりの滑走の途中で当たっても同じ。クッションはぶつかっても失敗にしない（手前で止まり、実行は続く）
- 命令列の取り消し操作も `undo` イベントとして記録する
- `play.groupRepeats: true` のレッスンでは、同じ方向を続けてタップすると新しいチップを追加せず
  直前のチップへ回数をまとめる（「した ×5」表示）。タップ操作自体は通常のレッスンと同一で、
  新しいジェスチャーは増やさない。`maxCommands` はまとめ後のチップ数で判定するため、
  まとめないと手数制限に収まらない構成にできる（Issue #48。詳細は `docs/lesson-schema.md`）
- `play.repeatBox: true` のレッスンでは、「はこ」→方向タップ→回数ボタン→「とじる」の順にタップして
  くりかえしの箱を作る（箱を開いている間、操作行は けす・かいすう・とじる になる。Issue #66）
- `play.initialCommands` のレッスンでは、`play` 開始時にキューへ指定した命令列を最初から
  積んでおく。誤った命令列を提示し、個別削除（×）と追加で直させるレッスン（例: なおす）で使う
  （Issue #31。詳細は `docs/lesson-schema.md`）
- プレイヤー駒は1マス450msでなめらかに移動し、通過マスに足あとを残す。壁停止時は250msの
  バウンス演出（進行方向へ軽く跳ねて戻る）。`prefers-reduced-motion`時はアニメーション無し
  （即時移動、足あとは表示される）。実装は`js/ui-grid.js`の`view`API（Issue #55）
- `play.items`（どんぐり等）がある盤面では、駒が乗ったマスのitemを回収して消す
  （拡大→フェードの演出、`pickup`効果音）。クリア条件は「ゴール到達 かつ 全item回収」。
  実装は`js/ui-grid.js`の`view.collectItem()`と`js/engine-grid.js`の`simulate()`が返す
  `pickups`/`remainingItems`（Issue #60。詳細は`docs/lesson-schema.md`）
- `play.keys` / `play.doors`（`[{x,y,color}]`、color=`red`/`blue`）がある盤面では、かぎのマスへ入ると同色のドアが開き通れる
  （`pickup`効果音。未所持の色のドアは壁と同じ失敗）。仕様は`docs/gimmicks.md`「keys」。
- `play.switches`（`[{x,y,targets:[{x,y}]}]`）がある盤面では、スイッチを踏むと`targets`の壁が消える（1回で固定）。仕様は`docs/gimmicks.md`「switches」。
- `predict`ステップの盤面はゴールを描かない（`goal: null`。itemsは経路に関わるため描く）。
  ゴール自体の見た目は星ではなく旗＋「ゴール」の文字（`shapeSvg('goal')`）。星はクリア演出・
  単元スタンプ専用で、ゴールと紛らわしくしない（Issue #80。予想ステップで星をゴール/答えと
  誤解された反応への対応）
- `play`は操作画面へ直接入る（課題カードはIssue #97で廃止）。操作画面には盤面・矢印ボタン・
  命令列・じっこうと、画面上部の1行の問い文（`step.text`。`.status-bar`）のみを置き、
  それ以外の説明要素は置かない。説明は`tutorial`（れんしゅう）と指ガイドで行う。`items`がある
  playでは問い文スロットに「のこり N」も表示し、回収ごとに減る
- 1レッスンの`play`は2〜4個（`p1`, `p2`…）のステージで構成し、だんだん難易度を上げる
  （後のステージほど最短手数・まとめ命令ありはチップ数が非減少。`tools/validate-lessons.mjs`が
  機械チェック）。途中ステージのクリアは`stage_clear`イベントのみを記録し、ボタンは
  「つぎの ステージ・もういちど」。最終ステージのクリアだけが`clear`（レッスン全体のクリア・
  単元スタンプの対象）になり、ボタンは「つぎへ・もういちど」。区分チップは複数ステージ時
  「うごかす 2/3」のように現在位置を添える。壁にぶつかった手が1つでもあれば、結果として
  ゴールに着いても正解にしない（Issue #104）
- 各レッスンで新しい操作が初登場する時、`intro`直後・最初の`play`より前に`kind: "tutorial"`
  （なぞり操作型チュートリアル）を、問題の操作画面とは見た目（背景色・見出し「れんしゅう」）を
  分けた説明専用画面として置く。手順は文章でなく実物ボタンと同じ見た目の「お手本列」＋現在の
  操作対象だけを光らせる誘導で示す。光るボタンに加え、次に押す方向を指すアイコンを
  `js/ui-hand.js`の`showHandHint`で重ねる（runは実行ボタン上、removeは対象チップ上でタップの
  動き、それ以外はパレット→命令列へのドラッグの動きで示す。未クリアレッスンのplay初回にも
  同様に1回だけ表示し、最初の操作でフェードアウトする。reduced-motion時は静止表示。Issue #95）。
  タップごとに番号付きゴースト矢印と1行キャプション（「うえに 1ます すすむ よてい」等）で予定の
  経路を示し、実行成功後は「れんしゅう おしまい／ここから もんだい」の区切り画面（同ステップ内の
  サブ画面）を挟んで`play`へ進む。「れんしゅうを とばす」でいつでもスキップできる。完了・
  スキップは`localStorage['steamkids.tutorialDone.<lessonId>']`に記録し、以後そのレッスンの
  tutorialは自動でスキップする（`intro`に小さく「れんしゅう する」を出し、選べばもう一度入れる）。
  失敗表示は無く、学習イベント（`run`/`clear`等）も記録しない
  （詳細は`docs/lesson-schema.md`「`tutorial`」。実装は`js/ui-tutorial.js`。Issue #81・#93・#98）
- 操作画面では、8秒操作が無ければ今の段階に対応する実物ボタンを3秒だけ光らせる（無操作の促し）。
  1ステップにつき最大2回まで（しつこくしない）。実装は`js/ui-guide.js`の`createIdleNudge`
  （Issue #89・#93）
- `#stage`の外（既存ヘッダー）に、今の区分（はじめに/れんしゅう/よそう/うごかす/まとめ）と
  単元名・レッスン名、「← もどる」・「🏠 えらぶ がめんへ」を常時表示する。もどるはstep 0で
  非表示、実行アニメーション中はどちらもdisabled。両者は誤タップで一緒に押さないよう、もどるは
  ヘッダー左側（タイトルの隣）、えらぶ がめんへはヘッダー右側（ダッシュボードリンクの隣）に
  離して置く。確認ダイアログは挟まず即座に遷移する（`window.confirm`も使わない）。誤操作の
  保険はUndoと、playの命令列の下書き保持（`S.drafts`。←で戻って再び進むと復元される）で行う。
  単元名は`lessons/index.json`から取得し、失敗時はレッスン名のみ表示してレッスン進行は止めない。
  実装は`js/ui-step.js`（Issue #91・#93・#95）
- `intro`の本文下に、ロボットが正解の道をたどってゴールへ到達する完成イメージを実盤面で見せる
  （`intro.demo`・`js/ui-demo.js`の`renderGoalDemo`）。`demo`のstart/goalは本番`play`の
  全ステージとは別の組を使い、答えのネタバレを避ける（`validate-lessons.mjs`が機械チェック）。
  自動再生は1回だけ（以前は2回再生する不具合があった）。「もういちど みる」で再生し直せる。
  再生中もヘッダーのもどる・えらぶ がめんへは操作でき、ステップを離れると裏の再生・効果音は
  即座に止まる。reduced-motion時も1手0.6秒のコマ送りで動かし、静止画にはしない（PC等で
  デモが動かない不具合の原因だった）。レッスンで新しく出てくる要素へ焦点を当てるため、
  `demo.showCommands`（命令チップ列を表示し実行中のチップを光らせる。`cmd-02`はまとめ表示
  `{dir, times}`で使う）・`demo.fixFrom`（先に誤った命令列を実行して失敗させ、一呼吸おいて
  正しい`commands`へ差し替えて再実行する「なおす」のデモ）を任意で持てる。`items`があれば
  盤面上に残数バッジも出す（Issue #97・#104）
- predictの固定命令列・tutorialのお手本列・playの命令列チップは、チップ間に「→」区切りを入れ、
  各チップに順番数字（①②③）を重ねる（実DOMにテキストを増やさずCSS疑似要素で描き、既存の
  厳密テキスト比較を壊さない。`js/ui-commands.js`の`renderOrderArrow`・`ORDER_BADGE_CLASS`。
  Issue #93）
- 正解の反応は`js/ui-reaction.js`の`showSuccess`に統一する（大きな星（`w-12`）＋「やったね！」
  （`text-2xl`）＋`fanfare`音＋振動＋盤面の紙ふぶき60粒・2秒＋ロボットのジャンプ2回・600ms。
  単発クリアの反応が薄いという実機指摘を受け、Issue #91時点より拡大した。Issue #104）。
  使う場所は`play`各ステージのクリアと、`predict`で正解した時。
  不正解時は`showHint`（「おしい！」＋否定語を使わないヒント文。`data-hint`のみを持ち
  `data-result`は付けない）。`play`のヒントは`diagnose(result, commands, spec)`（純粋関数。
  壁・盤外にぶつかった＞item未回収＞未到達の優先順位で原因を1つ選ぶ）に応じて、ぶつかった
  命令チップ・そのマス／残っているitem／止まったマスとゴールを盤面上に示す
  （`js/ui-grid.js`の`view.markCell`・`view.hintItems`・`view.shrug`）。`predict`のヒントは
  足あとを残したまま「ロボットは ここで とまったよ」を表示し、「もういちど よそう」
  （`data-action="retry-predict"`）で選び直せる。ヒントは次に命令を編集したら消える
  （`view.clearHints()`）。正解時も「つぎへ」に加え「もういちど よそう」を出す（Issue #93）
- 操作画面は固定パネル（`position: fixed`）を使わず、画面高さに収まる縦のflexで組む
  （`#app`が`h-[100dvh]`固定、盤面エリアは`flex-1`、パレット・命令列・じっこうは通常フローで
  重ならない）。1マスの大きさは固定64pxではなく可変（`js/ui-grid.js`の`computeCellSize`。
  盤面エリアの実寸から余白・マス間の隙間を差し引いた上で`clamp(8, 64)`で算出し
  `ResizeObserver`で画面回転にも追従する。下限は0除算防止のみが目的の8pxで、見た目の下限
  ではない（盤面はplay中はタップ対象ではない）。行数の多い盤面＋文字拡大＋操作パネルが
  重なる組み合わせでも、盤面がエリアより大きくなってロボットが隠れないことを優先する
  （Issue #99・#97）。
  結果（やったね／ヒント）は盤面に重ねず、問い文と同じスロットへ3秒だけトースト表示し、
  その後は問い文へ自動で戻る（`js/ui-toast.js`）。クリア時の「つぎへ・もういちど」は操作
  パネルのボタン行に表示し、押すまで消えない（Issue #97）。
  命令列は横に並ぶ64pxチップにし、チップ自体が取り消しボタン（はみ出す分は横スクロール）。
  パレットの矢印ボタンはタップに加えドラッグでも追加できる（命令列末尾へのドロップのみ。
  途中挿入はしない。`js/ui-commands.js`の`attachTapOrDrag`・`toggleGhostSlot`。Issue #95）。
  「⌫ ひとつ けす」（最後の1個を消す。`groupRepeats`でまとめられたチップ（×N）は1回分だけ
  減らし、1になった時だけチップごと消す。チップ×はチップ単位で消す。Issue #97）を追加する。
  実行が失敗すると、じっこうボタンの位置がそのまま橙色の「もういちど」に変わり（目線を
  動かさずに押せる）、命令列を編集すると自動で「じっこう」に戻る（Issue #91・#93）。
  「もういちど」（失敗後のretry・クリア後のreplay双方）は押した時点の正解・不正解に関わらず
  命令列を必ず`freshCommands`（`initialCommands`があれば初期の「ずれた」列、無ければ空）へ
  戻す（前回の命令列を残さない。Issue #104）
- ステップ進行は旧仕様の丸ドット（`.step-dot`）を区分アイコン付きのロードマップに置き換える
  （`intro`/`tutorial`/`play`各ステージ/`summary`をアイコン・番号・接続線で並べる。
  `.step-dot`・`data-current`のDOM契約は既存シナリオ互換のため維持する）。クリア済みレッスンでは
  `play`各ステージのノードが64px以上のボタンになり、タップで`goToStep`により直接そのステージへ
  移動できる（Issue #104）
- `summary`は大きな星（`w-32`）が回転しながら出る演出（reduced-motionは静止）＋「クリア！」＋
  レッスン名＋画面全体の紙ふぶき120粒・3秒＋`fanfare`音を表示する。このレッスンを開始してからの
  イベントをもとに、最大3枚の「できたこと」カード（`js/analytics.js`の`lessonAchievements`。
  最初のよそうの正誤・全ステージを1回ずつで／やり直しつつクリアしたか・最終ステージが最短手数と
  一致したかを判定する純粋関数。点数・割合・他人との比較は返さない）を表示し、単元のスタンプ
  （`js/ui-picker.js`の`stampSvg`。今回クリアしたレッスンのスタンプだけ「ぽん」と押される演出）を
  並べる。単元ぜんぶクリアなら、上記に加えメダル（`medalSvg`）・虹色紙ふぶき200粒・4秒・
  `grandFanfare`音・旗が揺れる演出とともに「{単元名} ぜんぶ クリア！」を表示する（以前の
  「しま クリア！」は単元名との対応が分かりにくかったため変更。Issue #104）。次のレッスンが
  あれば「つぎの レッスンへ」を表示する。実装は`js/ui-summary.js`（Issue #91・#104）

### 予想ステップの位置づけ（Issue #104で現行レッスンから全廃・語彙は将来向けに保持）

`kind: "predict"`を使う場合は**`play`ステップより前**に置き、**画面に提示された固定の命令列**を
見て到達マスを予想させる。子どもが自分で組んだ命令列に対して予想させる方式は採らない。

理由: 選択肢 `options` と正解 `answer` をレッスンJSONに固定でき、予想の正誤が全学習者で
同一基準になる。ダッシュボードの「予想を2回連続で外している」判定（`docs/dashboard.md`）が
成立するのはこの方式のときだけ。現行レッスンは命令を組む行為自体が「予想」を兼ねるため、
このステップは使わない。

## れんしゅう（シード生成レッスン。Issue #69）

単元の`practiceIds`に置くレッスン（スタンプ・旗の対象外。単元マップにはクリア回数のみ出し、比較・順位は出さない）。
`seedPick`（絵のたねコード入力）→`play`（`generator`から生成）→`summary`。イベントは`lessonId`固定のまま、
たね確定後の全イベントの`payload.seed`に4桁コード（`'0417'`形式）を記録する。

**ダッシュボードの「全学習者で同一基準」（予想・最短手数など）が成立するのは、`payload.seed`が同じ場合に限る。**
シードが違えば盤面が違うため、`seed`の異なる`run`/`clear`を横並びで比較・集計しない。

## 初回単元「めいれいでうごかす」

| # | レッスン | 内容 |
| --- | --- | --- |
| 1 | すすむ | 障害物を避けてゴールへ。3ステージでだんだん盤面が大きくなる |
| 2 | みじかくする | 同じ命令が続く道をまとめ命令（×N）で短く表現する |
| 3 | なおす | 用意された命令列が途中でズレている。誤りを見つけて直す |

各レッスンは`intro`→（レッスン1のみ`tutorial`）→`play`×3（`p1`〜`p3`。後のステージほど最短手数を
非減少にして難易度を上げる）→`summary`で構成する。レッスン1はP0、レッスン2・3はP5で
`lesson-author`スキル経由で追加し、Issue #104で predict廃止・3ステージ化した。

### レッスン1「すすむ」

`lessons/cmd-01-susumu.json`。`p1`は3×3・壁なし、`p2`は4×4・壁1つ（最短6手）、`p3`は5×5・
壁4つ（最短8手、中央に1マスだけ通り道がある）。`intro.demo`は`showCommands: true`で
命令チップが順に光る様子を見せる。

### レッスン2「みじかくする」

`lessons/cmd-02-mijikaku.json`。`groupRepeats: true`。`p1`は2チップ、`p2`は2チップ（盤面が
大きく手数が増える）、`p3`は壁2つで直線L字を塞ぎ3チップを要求する。`intro.demo`は
`showCommands: true`＋`commands`をまとめ表示（`{dir, times}`）にして「した×5・ひだり×2」を見せる。

### レッスン3「なおす」

`lessons/cmd-03-naosu.json`。`p1`は3×3で1手のズレ、`p2`は4×4で1手のズレ（P0からの継続）、
`p3`は5×5で1手のズレ（9手中）を直す。`intro.demo`は`fixFrom`（誤った命令列を実行して失敗）→
`commands`（正しい命令列で再実行しゴール）の2段構えで「なおす」を見せる。

### レッスン4・5「くりかえす」「はこで どんぐり」

`lessons/cmd-04-kurikaeshi.json`・`lessons/cmd-05-kurikaeshi-donguri.json`（Issue #66）。
`repeatBox: true`。箱に入れた方向の並びを回数ボタン（2〜4）で繰り返す（概念：ループ。問い「なんかい？」）。
cmd-04は`p1`が箱1個（2チップ）、`p2`が箱に2方向（3チップ）、`p3`が箱2個（5チップ）。cmd-05は
どんぐりを箱で集める2ステージ。`intro.demo`は箱の完成イメージ（`showCommands`）。

## 効果音（`js/sfx.js`、Issue #54）

Web Audio APIで合成する効果音のみ（音声ファイル・BGMなし）。単一API `play(name, opts)`。

| 名前 | 場面 | 長さ上限 |
| --- | --- | --- |
| `tap` | 命令追加（タップ） | 50ms |
| `snap` | 命令追加（ドラッグして命令列に吸着。Issue #95） | 30ms |
| `stack` | まとめ×2以上（`opts.count`で音程上昇） | 120ms |
| `remove` | 削除（個別・チップ×） | 120ms |
| `reset` | ぜんぶ けす（`remove`より速いピッチダウン。Issue #95） | 80ms |
| `run` | 実行開始（`playAnimation`の先頭で1回） | 300ms |
| `step` | 1マス移動（`opts.index`で音階が進む） | 150ms |
| `slide` | こおりの上を滑っている間の1マス（Issue #61。`step`と別音） | 150ms |
| `bump` | 壁で停止（ブザー禁止・柔らかいsine） | 250ms |
| `tryAgain` | 未達成（壁・item未回収・未到達。「首をかしげる」高めの2音。bumpと聞き分けられる音色、Issue #159） | 300ms |
| `cushion` | クッションに当たって手前で止まる（失敗ではない・やわらかい上下の音） | 200ms |
| `pickup` | アイテム取得（Issue #60） | 200ms |
| `reveal` | 予想の答え合わせ（一致・不一致で同じ音） | 200ms |
| `clear` | ゴール到達（ド・ミ・ソ・ド。現在は`predict`正解時のみ。Issue #104） | 460ms |
| `whoosh` | ステップ遷移（`goToStep`） | 200ms |
| `fanfare` | ステージクリア（`showSuccess`）・レッスンクリア（`summary`） | 860ms |
| `grandFanfare` | 単元ぜんぶクリア | 2030ms |

ミュート状態は`localStorage['steamkids.sound']`。`?sound=off`で未設定時のみ既定ミュート。
検証用に`window.__sfxLog`へ再生した音名を記録する（ミュート時は記録しない）。
