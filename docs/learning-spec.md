# 教材型と grid-runtime 仕様

教材型を実装するとき、レッスンを追加するときに読む。
全教材型に共通する3段構え（予想→実行→ズレを見る）とUI規則は PROJECT.md「学習体験の固定仕様」。

## 教材型

エンジンが持つ操作部品。**型は5つで打ち止めとし、以降はJSONで表現する。**

| ID | 型 | 想定単元 |
| --- | --- | --- |
| `grid-runtime` | グリッド上を命令で動かす | プログラミング、方向、座標 |
| `predict-slider` | 連続量を動かして結果を予想 | てこ、電流、濃度、比例、速さ |
| `sort-order` | 仕分け・並べ替え | 分類、手順、時系列 |
| `connect` | つなぐ | 回路、食物連鎖、対応関係 |
| `build` | くみたて | 実験の条件設計、式づくり |

MVP実装対象は `grid-runtime` と、全型共通の予想ステップのみ。

## grid-runtime 仕様

- 命令は**画面の絶対方向4種**（うえ・した・みぎ・ひだり）。キャラに向きを持たせない
- 命令の追加・削除はタップ。個別削除（×）と全消しの2つを用意する
- 実行は1手0.6秒。実行中の命令をハイライトする
- 座標は y が下向きに増加する（`up` は y−1、`down` は y+1）
- 壁・盤外に進もうとした手はその場で停止する。**失敗表示は出さない**
- 命令列の取り消し操作も `undo` イベントとして記録する
- `play.groupRepeats: true` のレッスンでは、同じ方向を続けてタップすると新しいチップを追加せず
  直前のチップへ回数をまとめる（「した ×5」表示）。タップ操作自体は通常のレッスンと同一で、
  新しいジェスチャーは増やさない。`maxCommands` はまとめ後のチップ数で判定するため、
  まとめないと手数制限に収まらない構成にできる（Issue #48。詳細は `docs/lesson-schema.md`）
- `play.initialCommands` のレッスンでは、`play` 開始時にキューへ指定した命令列を最初から
  積んでおく。誤った命令列を提示し、個別削除（×）と追加で直させるレッスン（例: なおす）で使う
  （Issue #31。詳細は `docs/lesson-schema.md`）
- プレイヤー駒は1マス450msでなめらかに移動し、通過マスに足あとを残す。壁停止時は250msの
  バウンス演出（進行方向へ軽く跳ねて戻る）。`prefers-reduced-motion`時はアニメーション無し
  （即時移動、足あとは表示される）。実装は`js/ui-grid.js`の`view`API（Issue #55）
- `play.items`（どんぐり等）がある盤面では、駒が乗ったマスのitemを回収して消す
  （拡大→フェードの演出、`pickup`効果音）。クリア条件は「ゴール到達 かつ 全item回収」。
  実装は`js/ui-grid.js`の`view.collectItem()`と`js/engine-grid.js`の`simulate()`が返す
  `pickups`/`remainingItems`（Issue #60。詳細は`docs/lesson-schema.md`）
- `predict`ステップの盤面はゴールを描かない（`goal: null`。itemsは経路に関わるため描く）。
  ゴール自体の見た目は星ではなく旗＋「ゴール」の文字（`shapeSvg('goal')`）。星はクリア演出・
  単元スタンプ専用で、ゴールと紛らわしくしない（Issue #80。予想ステップで星をゴール/答えと
  誤解された反応への対応）
- `play`ステップは盤面上部に「もくひょう行」（旗アイコン＋「ゴール」、items有時は
  どんぐりアイコン＋「のこり N」）を表示する。`N`は実行開始・もういちど時に`items.length`へ
  戻り、回収ごとに1減る（Issue #80）
- 各単元1本目のみ、`intro`直後・`predict`より前に`kind: "tutorial"`（なぞり操作型チュートリアル）
  を置く。文字を読ませない方針のため、手順は文章でなく実物ボタンと同じ見た目の「お手本列」＋
  現在の操作対象だけを光らせる誘導で示す。失敗表示は無く、学習イベント（`run`/`clear`等）も
  記録しない（詳細は`docs/lesson-schema.md`「`tutorial`」。Issue #81）
- `predict`・`play`（tutorial以外）は盤面の上に「やりかた帯」（操作の流れをブロック図＋短文で
  示す帯。例：①やじるしを おす→②めいれいが ならぶ→③じっこうを おす）を常時表示する。
  次にやる段階だけ控えめに強調し、済んだ段階はチェック済み表示にする（点滅はさせない）。
  `initialCommands`があるレッスンは「①×で けす→②やじるしで たす→③じっこう」になる。
  レッスンJSONの変更は不要（`step.initialCommands`の有無から自動で決まる）。実行中・結果表示中は
  強調を消す。tutorialには出さない（お手本列と光るボタンで既に示しているため二重にしない）
- 上記に加え、8秒操作が無ければ今の段階に対応する実物ボタンを3秒だけ光らせる（無操作の促し）。
  1ステップにつき最大2回まで（しつこくしない）。実装は`js/ui-guide.js`
  （`renderHowTo`・`createIdleNudge`。Issue #89）
- `#stage`の外（既存ヘッダー左側）に、今の区分（はじめに/れんしゅう/よそう/うごかす/まとめ）と
  単元名・レッスン名、「← もどる」（`goToStep(stepIndex-1)`）を常時表示する。もどるはstep 0で
  非表示、実行アニメーション中はdisabled。単元名は`lessons/index.json`から取得し、失敗時は
  レッスン名のみ表示してレッスン進行は止めない。実装は`js/ui-step.js`（Issue #91）
- `intro`の本文下に、このレッスンで何をするかの簡易デモ（`js/ui-demo.js`の`renderDemo`）を表示する。
  `predict`・`play`（`tutorial`以外）の先頭には区分バナー＋デモを表示し、最初の操作でデモを畳んで
  見出し1行にする。デモは実盤面ではなく操作の流れを示す最小限のアイコン列＋指アイコンで、
  CSSアニメで2周再生して停止し「もういちど みる」で再生し直せる。reduced-motion時は①②③を
  静止で並べる（Issue #91）
- 正解の反応は`js/ui-reaction.js`の`showSuccess`に統一する（星＋「やったね！」＋`clear`音＋
  振動＋盤面の紙ふぶき）。使う場所は`play`・`tutorial`のクリアと、`predict`で正解した時。
  不正解時は`showHint`（「おしい！」＋否定語を使わないヒント文。`data-hint`のみを持ち
  `data-result`は付けない）。`play`のヒントは`diagnose(result, commands, spec)`（純粋関数。
  壁・盤外にぶつかった＞item未回収＞未到達の優先順位で原因を1つ選ぶ）に応じて、ぶつかった
  命令チップ・そのマス／残っているitem／止まったマスとゴールを盤面上に示す
  （`js/ui-grid.js`の`view.markCell`・`view.hintItems`・`view.shrug`）。`predict`のヒントは
  足あとを残したまま「ロボットは ここで とまったよ」を表示し、「もういちど よそう」
  （`data-action="retry-predict"`）で選び直せる。ヒントは次に命令を編集したら消える
  （`view.clearHints()`）
- md未満では、パレット・命令列・操作ボタンを画面下に固定する操作パネル（`position: fixed`）に
  まとめ、盤面が長くても「じっこう」が常に見えるようにする。命令列は横に並ぶ48pxチップにし、
  チップ自体が取り消しボタン（はみ出す分は横スクロール）。「⌫ ひとつ けす」（最後の1個を消す）
  を追加する。実行が失敗すると、じっこうボタンの位置がそのまま橙色の「もういちど」に変わり
  （目線を動かさずに押せる）、命令列を編集すると自動で「じっこう」に戻る（Issue #91）
- `summary`は星のはじける演出（reduced-motionは静止）＋「クリア！」＋レッスン名を表示する。
  このレッスンを開始してからのイベントをもとに、最大3枚の「できたこと」カード
  （`js/analytics.js`の`lessonAchievements`。最初のよそうの正誤・1回で／複数回でクリアしたか・
  最短手数と一致したかを判定する純粋関数。点数・割合・他人との比較は返さない）を表示し、
  単元のスタンプ（`js/ui-picker.js`の`stampSvg`）を並べて全クリアなら「しま クリア！」、
  次のレッスンがあれば「つぎの レッスンへ」を表示する。実装は`js/ui-summary.js`（Issue #91）

### 予想ステップの位置づけ（確定事項）

予想は **`play` ステップより前** に置き、**画面に提示された固定の命令列**を見て到達マスを
予想させる。子どもが自分で組んだ命令列に対して予想させる方式は採らない。

理由: 選択肢 `options` と正解 `answer` をレッスンJSONに固定でき、予想の正誤が全学習者で
同一基準になる。ダッシュボードの「予想を2回連続で外している」判定（`docs/dashboard.md`）が
成立するのはこの方式のときだけ。

## 初回単元「めいれいでうごかす」

| # | レッスン | 内容 |
| --- | --- | --- |
| 1 | すすむ | 4×4、障害物1つ。命令4〜6個でゴール。実行前に到達マスを予想 |
| 2 | みじかくする | 同じ命令が5回続く道。手数制限で「したへ5」にまとめさせる |
| 3 | なおす | 用意された命令列が途中でズレている。誤りを見つけて直す |

レッスン1はP0、レッスン2・3はP5で`lesson-author`スキル経由で追加した（Issue #30, #31）。

### レッスン1「すすむ」の確定値（P0実装対象）

| step | kind | 内容 |
| --- | --- | --- |
| s1 | intro | 「ゴールまで すすもう」 |
| s2 | predict | 「ロボットは どこで とまる？」固定命令列 `[up, up, right]` を提示。start `(0,3)` から到達するのは `(1,1)`。選択肢 A=`(1,2)` / B=`(1,1)` / C=`(2,1)`、`answer` は `"B"`。選択後に自動実行し、予想マスと結果マスを並べて表示する |
| s3 | play | 「ロボットを ゴールへ うごかそう」4×4、start `(0,3)`、goal `(3,0)`、walls `[(2,2)]`、`allowedCommands: [up,down,left,right]`、`maxCommands: 8` |
| s4 | summary | 「めいれいの じゅんばんが だいじ」 |

`play` の最短解は6手（up,up,up,right,right,right）で、経路
`(0,3)→(0,2)→(0,1)→(0,0)→(1,0)→(2,0)→(3,0)` は壁 `(2,2)` を通らない。

### レッスン2「みじかくする」の確定値（P5実装対象）

`lessons/cmd-02-mijikaku.json`。3×6、start `(0,0)`、goal `(2,5)`、壁なし。`groupRepeats: true`、
`maxCommands: 3`。同方向連続（down×5・right×2）をまとめないと3チップに収まらない
（まとめれば2チップで到達）。

### レッスン3「なおす」の確定値（P5実装対象）

`lessons/cmd-03-naosu.json`。4×4、start `(0,3)`、goal `(3,3)`、壁なし。
`initialCommands: [right,right,up,right]`（3手目の`up`が誤り。到達点は`(3,2)`でゴール未達）。
`up`を削除した`[right,right,right]`でゴール `(3,3)` に到達する。`maxCommands: 4`。

## 効果音（`js/sfx.js`、Issue #54）

Web Audio APIで合成する効果音のみ（音声ファイル・BGMなし）。単一API `play(name, opts)`。

| 名前 | 場面 | 長さ上限 |
| --- | --- | --- |
| `tap` | 命令追加 | 80ms |
| `stack` | まとめ×2以上（`opts.count`で音程上昇） | 120ms |
| `remove` | 削除（個別・全消し） | 120ms |
| `run` | 実行開始（`playAnimation`の先頭で1回） | 300ms |
| `step` | 1マス移動（`opts.index`で音階が進む） | 150ms |
| `bump` | 壁で停止（ブザー禁止・柔らかいsine） | 250ms |
| `pickup` | アイテム取得（Issue #60） | 200ms |
| `reveal` | 予想の答え合わせ（一致・不一致で同じ音） | 200ms |
| `clear` | ゴール到達（ド・ミ・ソ・ド） | 1200ms |
| `whoosh` | ステップ遷移（`goToStep`） | 200ms |

ミュート状態は`localStorage['steamkids.sound']`。`?sound=off`で未設定時のみ既定ミュート。
検証用に`window.__sfxLog`へ再生した音名を記録する（ミュート時は記録しない）。
